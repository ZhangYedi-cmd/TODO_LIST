# 题材档案库 · 分析方法论（与参考档案 v6 规则一致）

每份档案只回答三个问题，其余一切都为它们服务：

1. **这条催化是真的吗？**（变化是否为「实」，数字是否精确、可追溯）
2. **A 股定价了没有？**（未定价 / 部分定价 / 已定价——用盘面数据说话，扣 beta 看超额）
3. **定价应该落在谁身上？**（受益 / 中性 / 受损的边界；主攻 / 情绪 / 观察的分层；用什么信号验证或证伪）

它不是新闻摘要，也不是荐股：全文不含价位、仓位、买卖建议（第 07 步固定为「交易者自管，本图不涉及。」）。

---

## 1. 选题：每日从候选里挑什么

### 1.1 入库四判据

| 判据 | 含义 | 判定方法 |
|---|---|---|
| ① 有精确数字 | 变化可量化：价格/幅度/税率/产能/订单/库存/缺口… | 标题或正文能写出「X→Y」「+N%」「N 万吨」 |
| ② 有预期差 | 市场尚未（或只在错误环节）定价 | 消息在盘后/夜间/周末落地；或核心环节标的当日超额 ≈0 / 反向 |
| ③ 有可证伪胜负手 | 存在客观时点或指标能判对错 | 能写出 1 个硬时点（生效日、财报、下一期报价、复审） |
| ④ A 股可映射（隐含前提） | A 股有收入占比够高的标的 | 产业链上能找到主营相关的上市公司；涉案品类占其收入明显（参考阈值：≥5–10%） |

- **四条都满足 → 正式档**（`archiveLevel: 正式档`）。
- **①③ 满足，但②不成立（板块已爆发、预期差被抹平）或④不成立（A 股无标的） → 降档入库**：`archiveLevel: 降档`，`grade.tone: warn`，定性写「题材催化级」，`downgradeBadge` 固定「⚑ 降档入库 · 只配情绪波段，不格局中线」。降档档案的价值是**记录与建立基准**（税率区间、程序节奏、传导为何断裂），宁可写「本档无合格主攻标的」也不硬凑沾边标的。
- **①不满足 → 不入库**（纯观点、纯宏观评论、无数字的传闻）。

### 1.2 新建档案 vs 主线更新

- 同一主线、**同一变量**的新进展（二段催化、数据更新、证伪信号出现）→ **不新建**，在原档案 `timeline` 末尾追加一条，并按新事实更新 `pricing / rings / positionNote / signals`，必要时调整 `grade`。
- **新变量**（新品类、新环节、新的驱动）→ 新建档案；`mainline` 尽量沿用已有主线名（`AI算力与电力配套`、`能源地缘·中东供断与成品油`、`资源品涨价与煤焦链`、`农业·粮食与化肥`、`反内卷·供给侧调控`、`化工涨价链`、`贵金属·货币信用重估`、`贸易摩擦·反倾销`、`创新药出海` …），这样主线联动会自动把它和同主线档案互链。

### 1.3 数量与偏好

- 每个交易日 **2–4 份新档案**（候选质量差时 1 份即可，宁缺毋滥）。主线更新另计、不占名额：当天新闻触发了哪条已有档案的验证/证伪信号，就更新哪条。
- 优先级：价格/供给类硬变量（涨价函、历史新高、停产减产、EOL、出口/关税/反倾销、订单与产能）＞ 政策落地 ＞ 海外映射 ＞ 资金/宏观。
- 盘后、夜间、周末落地的消息天然带预期差，优先；已经涨停潮式定价的，大概率降档或定为「已定价」。
- 「标题利好、内容利空」「真利好但已定价」同样值得写——作为 ⚠ 证伪型样本，防止下次误判。

## 2. 定性：`grade`（emoji + 定性 + 矛盾点）

格式：`<emoji> <定性> · <一句话矛盾点>`，例：`⚡ 供给硬缺口 · 上游芯片未定价、下游模块已抢跑`。

| tone | emoji | 统计口径 | 什么时候用 |
|---|---|---|---|
| `fire` | 🔥 | 已启动 | 逻辑已被资金认领、处在主升（股价环 = 主升中段/已启动），通常「部分定价」 |
| `bolt` | ⚡ | 未充分定价 | 变化为实、传导成立，但股价端未动或只动了错的环节——**核心预期差** |
| `warn` | ⚠ | 风险信号 | 证伪型（标题利好内容利空 / 真利好但已定价）、A 股映射断裂、所有降档档案 |

**定性词表**（沿用，必要时可新造同构词）：供给冲击型、供给硬缺口、供给退出型、供给恢复冲击、涨价实锤级、涨价预期上调型、成本推动型涨价、需求爆发级、政策放开型、供给侧调控型、资金定价型、产业兑现级、海外映射级、超级周期主升、国产替代主升、题材催化级（降档专用）。

**矛盾点**：一句话点出「定价错位」在哪，例如「美股已定价、A股CPU链完全零反应」「函涨 4.5%、基准价只涨 1%，龙头发函当日 -4.34%」「商品端创历史纪录，权益端按停火预期反向下杀」。

### 2.1 驱动类型 `driver`（五选一）

- **产业周期**：供需、价格、产能、技术路线驱动（最常见）。
- **地缘冲突**：战争、袭击、制裁、航道中断驱动。
- **政策驱动**：国内外政策、关税、反倾销、出口管制、产能调控。
- **证伪型**：催化为真但逻辑方向与标题相反，或利好已被定价——档案的作用是「防误判」。
- **映射型**：海外事件/海外资产已定价，考察 A 股映射链（如美股龙头大涨后 A 股同链）。

## 3. 定价状态 `pricing`：用盘面说话

先跑 `stock_lookup.py`（或 web 检索）拿到数据，再判定。**三条纪律**：

1. **扣 beta**：超额 = 个股涨跌幅 − 上证涨跌幅（写成「超额 -1.91pct」）。科技爆发日 / 普跌日要点明（「科技股爆发日，需扣 beta」）。
2. **看时点**：消息首发时间对照交易时段——盘中发布看当日；**盘后（15:00 后）/夜间/周末发布，当日收盘价不含该信息**，要看下一交易日；消息面时滞（调价函 9/11 发、媒体 9/16 才扩散）要写出来。
3. **看结构**：链内逐环节排序（上游/中游/下游、龙头/跟随），是否进入当日涨停题材地图，涨停家数中有无该题材。

| 状态 | 盘面特征 |
|---|---|
| **未定价** | 核心环节标的超额在 ±1pct 内或反向；板块不在涨停题材地图；「产业连涨三轮、股价零反应」 |
| **部分定价** | 只有部分环节/部分标的动了：下游或龙头抢跑而上游未动；小票异动而龙头未动；已涨一段但仍有未兑现环节 |
| **已定价** | 核心标的事前已大涨（20 日/年内涨幅大），催化当日冲高回落或反向收绿；或板块当日涨停潮式爆发、预期差被抹平 |

`pricing` 只能取这三个值（不要写「已部分定价」）。

### 3.1 定价状态详版 `pricingDetail`（300–800 字，三段式）

1. **催化时点**：首发来源 + 精确时间（「财联社 9/16 13:04」），扩散路径，盘中/盘后/周末，时滞。
2. **盘面状态**：指数涨跌；链内按环节逐只列「名称 涨跌幅（超额 ±x.xxpct，换手、成交）」；多日路径（「9/11 -4.34%、9/14 +2.50%…四日累计仍为负」）；涨停家数与题材地图。
3. **结论**：市场把它定性为『A』而非『B』（例：『托底式试探』而非『景气反转』；『成本挤压』而非『涨价受益』）。

`positionNote`（55–85 字）是它的一句话版：最硬的事实数字 + 定价状态结论。

## 4. 核心事实 `facts`（6–8 张卡）

- 第 1 张：`核心事实` / `事件本体` / `核心事件`——事件本体、精确数字、出处与时间。
- 中间 3–5 张：量级（为什么大/小）、供需与库存、结构与格局（谁受益谁受损）、同期对照或产业扩散、历史位置。卡片标题要带观点（「为什么是三安（而非纯光模块厂）」「700 元的分量」「套利为何仍然成立」）。
- **争议点**（`warn: true`，标题以「争议点」开头或写明反面）：最强的反方论据——涨价未必落到利润、总额≠到手、口径噪音、成本同步上涨…
- 最后一张：**盘面验证**——指数、链内逐只涨跌与超额、成交/换手、涨停家数、结论一句。

每张 150–250 字，数字优先，出处写在括号里。

> 本文件里的字数是**写作目标**；`validate_case.py` 的长度区间是更宽的**容差**（取自参考档案的实际分布），只在超出容差时给 WARN。

## 5. 主线更新 `timeline`

每条 = `when`（`YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM`）+ `what`（事件，带数字）+ `why`（它在主线里的角色：建档时点 / 第一段催化 / 二段催化 / 验证信号 / 证伪信号 / 盘后扩散未定价）。建档时至少 1 条；持续跟踪的档案按时间追加。

## 6. 逻辑推演 `verdict`（500–700 字）

两种写法任选其一，但都要覆盖三件事 + 隐藏面：

- 「这是「X」催化，**三个要害**：一是……二是……三是……。隐藏面：……」
- 「① **分水岭时点**是……② **传导的关键约束**是……③ **待验证的核心变量**是……<strong>隐藏面</strong>：……」

隐藏面 = 多数人没注意到的反直觉细节（配合方税率反而更高、涨价的发动者自己不被买、战争险溢价而非运力紧张…）。

## 7. 产业链四环 `rings` + 闭合度

| 环 | 问题 | 常用判词 |
|---|---|---|
| 变化 | 事实是否为真、强度 | 实 / 实且加速 / 实且极强 / 待证实 |
| 影响 | 对产业供需、价值量的作用 | 强 / 直接 / 强但间接 / 分化 / 弱 / 反向 / 已兑现 |
| 业绩 | 能否落进利润表 | 直接 / 分化 / 存疑 / 未兑现 / 已兑现部分 / 已透支 / 映射断裂 / 无映射 |
| 股价 | 定价状态 | 未动 / 结构未动 / 待观察 / 主升中段 / 已启动 / 反向 / 已透支 / 主体错位 |

- 每环 **2 个要点**，每点 25–45 字，带数字。
- `ringSummary`：「变化X、影响Y、业绩Z、股价W——一句话结论」（40–70 字）。
- **闭合度**（写进 `assessment[0]`，形如「闭合度 <strong>60%</strong>：……」）：每环 0–25 分再相加、取 5 的倍数。
  - 成立且有硬数字 = 25；成立但间接/待证实/已兑现 = 15；分化/存疑/部分 = 10；弱 = 5；断裂/反向/无映射 = 0。
  - 例：实 25 + 强 25 + 存疑 10 + 未动 0 = 60%；实 25 + 实 25 + 直接 25 + 主升中段 15 = 90%。
  - 闭合度衡量**逻辑完整度**，不是机会大小：股价环「未动」得 0 分，但它恰恰是预期差。
- `assessment` 固定三条：① 闭合度 + 逐环说明；② **边界**：受益 / 中性 / 受损分别是谁（要切开，例如「受益的是上游 IDM；中性偏受益的是已自供的模块厂；受损的是纯模块代工」）；③ **主线联动**：与哪些已有档案（写 id）同向验证或互为反证。

## 8. 环节 × 标的 × 映射逻辑

两个维度同时用：

### 8.1 交易角色（`stockTiers`，按此顺序，没有的档可省略）

| 档 | 标题 | 选谁 | 张数 |
|---|---|---|---|
| 🔥 主攻 | `🔥 主攻·资源映射`（也可 `🔥 主攻·<细分>`） | 传导链最短、纯度最高、弹性最直接 | 2–3 |
| 🏛️ 容量中军 | `🏛️ 容量中军` | 大市值、机构配置型，链上的流动性锚 | 0–2 |
| 🧬 观察 | `🧬 观察·待验证` | 逻辑成立但需要数据确认，或存在明显约束 | 1–3 |
| ⚡ 情绪小票 | `⚡ 情绪小票` | 小市值、当日异动/涨停、概念纯度未必高，**必须写题材基因** | 1–3 |
| 👑 情绪龙 | `👑 情绪龙` | 板块最高板 / 成交最大 / 认知锚，**必须写题材基因** | 0–1 |

每档的 `driver` 默认等于档案 `driver`，映射型的情绪档写 `映射型`。合计 5–11 张。

卡片字段：`name` / `code`（6 位）/ `tag`（一句话定位，≤20 字）/ `cap`（留空，打包时按行情自动生成「价格 · 流通市值 · 日期 涨跌」）/ `logic`（映射逻辑 ≤18 字，可附当日涨跌「IDM 全链·9/10 -0.10%」）/ `detail`（2–3 句：为什么在这一档 + 当日盘面数字）/ `gene`（题材基因：历次同类行情中的角色，例「2021 煤焦油行情中曾三连板」）/ `risk`（该标的独有风险）。

### 8.2 传导位置

- **⛓️ 核心环节 · 传导链最短**（`coreLinks`，2–3 家）：`logic` 固定三段「产业地位 | 弹性来源 | 约束条件」；`detail` 200–300 字（地位、结构性优势、弹性来源、约束、当日盘面）；`confirm` 为客观确认条件，用「 / 」分隔；`risk`。
- **🔗 延伸环节 · 传导链较远**（`extendedLinks`，1–3 家）：`logic` 一句话说明为什么远；`detail` 100–180 字；`risk`。
- **🚫 不在传导链上**（`notInChain`，2–4 条，`code: "—"`）：三类都要考虑——① 蹭概念的公司/方向（「CPO 涨停的 PCB 票」）；② 错误推演模板（「把反倾销当供给侧利好」）；③ 成本受损方（下游整机、纯代工）。
- 没有合格的 A 股标的时：`coreLinks` 写一张 `（本档无合格主攻标的）`（`code: "—"`），并降档。

### 8.3 📜 历史妖股记忆 / 同类行情参照（`history`，3–4 条）

每条：年份 + 同类事件 + 当时的标的与涨跌/倍数 + 一句教训；最后一条常写本主线本轮之前的节点（「2026 上半年两轮涨价：股价端基本无反应」）。

## 9. 合规决策链 · 八要素（`decisionChain`，固定 8 步）

| 步 | 名称 | 写法 |
|---|---|---|
| 01 | 定性 | `<strong>定性词</strong>：一句话。基准参照：<年份> <同类事件>，<结果数字>。` |
| 02 | 主攻优先级 | `A ＞ B ＞ C。排序理由：……`（按纯度/弹性/兑现质量） |
| 03 | 情绪优先级 | `X（情绪龙）＞ Y ＞ Z。gene：……`（无情绪票时写「无」并说明） |
| 04 | 确认条件 | `若 <客观条件1><strong>且</strong><客观条件2> → 逻辑状态由「…」升为「…」。` 只写客观条件 |
| 05 | 验证点 | `① … ② … ③ …` |
| 06 | 证伪点 | `① … ② … ③ …` |
| 07 | 仓位 | 固定：`交易者自管，本图不涉及。`（`style: dim`） |
| 08 | 特别提醒 | 100–220 字：最大的陷阱/反直觉点/盯哪一个指标（`style: alert`） |

## 10. 情景推演 `scenarios`（3–4 个互斥分支）

第一个分支写基准情形（标题加「（基准情形）」或按概率最高排在首位）。每支：`trigger`（可观察的触发条件，用「 / 」并列）→ `state`（触发后逻辑变成什么、哪一环被打通/切断、分层是否要调整）→ `signal`（观察信号）。分支之间要互斥、可证伪；不写操作建议。

## 11. 信号对照台 `signals`

`verify`（出现 → 逻辑成立度提升）与 `falsify`（出现 → 下降）各 4–5 条，每条 25–45 字，**具体、可测、带阈值或时点**（「100G EML 现货站稳 8 美元上方」「三季报毛利率环比未改善」）。可以在证伪信号里写与其他档案的交叉验证（写档案 id）。

## 12. 跟踪日历 `calendar`（3–5 项）

`when`（「10 月下旬」「9 月下旬–10 月」「2026 Q4」「10/5」「持续」「每周四」）+ `what`（看什么）+ `why`（为什么这个时点是裁判）。

## 13. 数据来源 `sources`

按「来源（时间）」列出，用「 ｜ 」分隔：快讯与媒体（带时分）、公司公告/互动平台、研报（机构 + 日期）、行业数据（生意社/隆众/SMM/…）、行情数据（「东财行情 9/24」「iFinD 盘面 9/24」或「Web 检索 9/24」）。不要写本地文件路径。

## 14. 写作风格（与参考档案一致）

- **数字优先**：每个判断带数字、单位、日期。日期写「9/16」，时刻写「13:04」，涨跌写「+2.81%」，超额写「超额 -1.91pct」，金额写「成交 11.1 亿」「流通 638 亿」「1.01 万亿」。
- 概念与标签用「」，被引用的定性用『』；转折用「——」。
- 关键结论用 `<strong>…</strong>` 加粗（每段 2–4 处，不要整段加粗）；段落用 `<br><br>` 分隔。字段里只允许 `<strong> <b> <br> <em>`。
- 用「本档」「本条逻辑」「链内」「传导链」等档案口吻；客观、克制，不用「我们认为」「强烈推荐」。
- 同一数字在全档内口径一致（价格、涨跌、日期）。

## 15. 合规红线（validator 会拦）
